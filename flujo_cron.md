el script busca en la base de datos los cron guardados.
Luego implementa la logica para saber cual cron se debe ejecutar.
Luego se llama a un servicio dentro de la aplicacion, que va a recibir el tipo de cron, tipo de notificacion(whatsapp o email), id de la ciudadela, si hay mas campos que consideres a enviar, se lo envia. 
El servicio sera un post donde recibira toda esa data, y sera un servicio con authorizacion, el servicio llamara a un archivo facade donde estara la logica de negocio. en esa clase facade, llamaremos a los servicios de email. pero antes debemos sacar la lista de usuarios quienes recibiran el correo, si la tarea cron es de recordatorio de pago, debemos buscar en la lista de clientes, la fecha de pagos que ellos han elegido, y contar, por ejemplo si el cliente paga los 15 de cada mes, y la fecha actual es 10 del mes,se debe sacar la diferencia de dias, si es mayor a 5 dias, no se envia el correo a ese cliente, si es menor o igual si se le envia el correo. el valor de 5 dias guardalo en una variable de ambiente que se llame DAYS_REST_FOR_PAY = 5 para tener ese valor parametrizado.
Ahora si el cron es por mora, debemos buscar todos los clientes cuya fecha de pago ya se haya pasado con la fecha actual. busca en la tabla correspondiente si se guarda ese valor, en caso contrario indicamelo para realizar ese paso antes de comenzar con esa logica. ahora si el cron es por cumpleaños, debemos sacar todos los clientes que cumplan años el dia que se corre el cron, y enviar un mail. 
Por ahora implementa la logica donde tomas los destinatarios, e imprimelos en consola para validar, la parte del correo aun la esta haciendo otro equipo, asi que de ello no te encargues. toda esta bifurcacion y logica, debe de estar implementada con SOLID para llevar un codigo limpio, respeta por lo menos los dos primeros principios.
